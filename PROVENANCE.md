# Where this code came from

Every tree in this repository is **source**. Edit it here.

That is a change of policy, made on 2026-09-08, and this file used to say the
opposite. It was `plugins/VENDORED.txt`, and most of it was a warning: these
directories are copies, a change made in one is lost the next time anybody
re-vendors, and lost silently. Three of the four plugins, `ainar-node/`,
`.agents/skills/`, `datalayer/` and `golden/` were all copies of trees that lived
in sibling checkouts, and the file's job was to name the sibling so a change
could be ported back before a re-vendor overwrote it.

Nothing re-vendors now. There is no build step pointed at this repository, no
`python -m exo setup` writing into it, and no Python anywhere in it — the last
four commands that needed it were ported on 2026-09-08 (see *The Python port*
below). What is left is this file: a record of where each tree originally came
from, kept because knowing the origin of a piece of code is worth something long
after the link to it is cut.

Each was copied on **2026-09-04** unless a later date is given. The paths are
where they were on that day; whether those checkouts still exist is not this
repository's concern.

| Tree | Taken from | How it was produced there |
|---|---|---|

| `ainar/mcp/widget-assets/` | `ProfessorHarness/ainar` | hand-written |
| `golden/` | `ProfessorHarness/golden` | written by `python -m ainar golden`, which is not ported |

### Two copies that are not accidents

**The widget assets exist twice**, in `ainar/mcp/widget-assets/` and
`ainar-node/widget-assets/`, and a third time under
`plugins/dsh-ainar-course-model/widget-assets/`. `src/mcp/widgets.ts` searches
several locations and finds the copy inside `ainar-node`;
`test/widgets.test.ts` opens `ainar/mcp/widget-assets/template.js` by a
hardcoded path. One copy satisfies the code and the other satisfies its test;
deleting either breaks one of them. The `ainar/` directory exists for no other
reason.

**`golden/` is a fixture corpus, not a library.** `postgres-course-store`'s tests
open `golden/CSS-4008/bundle.json` by a path relative to the repository root, so
it has to sit at the root. `npm run golden` compares this project's output
against it, and `npm run validator` does the same for the 98 validator
mutations. Both corpora were produced by the Python implementation before that
implementation was cut loose, which is exactly what makes them worth keeping:
they are a record of what the code this port replaces actually emitted.
`golden/CSS-4008/import.sql` was added on 2026-09-08 for the same reason.

### One copy that is more than a copy

`plugins/professor-skills/` was taken with a plain recursive copy rather than
through `exo setup`, which deliberately omits `node_modules`. So it carries the
63 MB of dependencies that had been installed in the source checkout — which is
why `pres` works here without the separate `npm install` its own README asks
for.

## The Python port

Four commands used to print *"run `python -m ainar` for that"* and exit 1:
`lms`, `score-items`, `sql` and `export`. Two more — `dashboard` and `page` —
were not in the Node CLI at all. All six were ported on **2026-09-08**, and each
was checked against the implementation it replaces by running both over the same
course and comparing the output:

| Command | Ported to | How it was checked |
|---|---|---|
| `score-items` | `src/scoring.ts` | `test/scoring.test.ts`, and `round()` compared against Python's on the values a small cohort produces |
| `export` | `src/export.ts` | `bundle.json` compared field-for-field against `golden/CSS-4008/bundle.json` |
| `sql` | `src/sqlgen.ts`, `src/sql/schema.sql` | 655 lines diffed against Python's output; `golden/CSS-4008/import.sql` pins it |
| `dashboard` | `src/dashboard.ts` | the rendered HTML is byte-identical to Python's |
| `page` | `src/page.ts`, `src/templates.ts`, `src/safety.ts` | head, footer and copied materials byte-identical; the body differs only by this repository's own widget assets |
| `lms` | `src/lms/` | `plan`, `diff` and the two CSV outputs byte-identical to Python's |

### Three things the port could not carry across, and one it improved

* **`sqlgen`**: a whole-numbered float inside a free-form `extensions` map prints
  as `1` where Python printed `1.0`. The JavaScript YAML parser has discarded
  the distinction before the generator sees it. Three lines of a 655-line script;
  `test/sqlgen.test.ts` names every line it is allowed to affect.
* **`lms` ledger**: the same, for `~/.ainar/sync/*.json`. Both implementations
  read either spelling correctly.
* **`page`**: Python shelled out to `node bin/prerender-widget.mjs` and had a
  fallback for "Node is not on PATH". This *is* Node, so the prerenderer is
  imported and run in process, and `--static` — the flag that turned that
  fallback into an error — is accepted and ignored.
* **`sheets`**: signing a service-account assertion needs RSA, which Python's
  standard library does not do, so upstream had an optional `google-auth`
  dependency. Node's `crypto` signs RS256, so that dependency is gone and the
  JWT flow is sixty visible lines in `src/lms/sheets.ts`.

### What was deliberately not ported

`notion` (pull/diff/push), `paper`, `golden --write` and `exam-setup` stayed
behind. Nothing in this repository invokes any of them. The ledger still carries
Notion's half of its file untouched, so a professor who has one keeps it — see
`src/lms/ledger.ts`.

## Changes made here that upstream does not have

Kept as a list because it is the interesting half of the history: these are
decisions this project made, not code it inherited.

**Policy**

* `src/drafts.ts` — `concepts` and `modules` dropped from `DRAFTABLE`, so the
  structure of a course is authored straight into `courses/` and only what
  reaches a student through a grade waits for approval.
* `src/approve.ts` — `stageDocuments` returns staged ids; the claim-file
  mechanism removed; a non-draftable collection fails loudly.

**New here**

* `src/evidence.ts`, `src/progress.ts` roll-up, `src/roster.ts` — the roster's
  HMAC pseudonyms, base32 and private store, with the derivation pinned to
  RFC 4648 and RFC 4231 vectors, which is what makes a second implementation of
  it safe.
* Subgroups, threaded through `bundle`, `progress`, `gradebook`, `inbox`,
  `outline` and the MCP tools: `--group` narrows a view to one subgroup, an
  activity with no group belongs to the whole run, and a label the run does not
  have is refused rather than answered with an empty class.
* Enrollment status: an import marks a student the export no longer lists as
  `dropped` rather than dropping the row.
* `ainar-node/widget-assets/` — the compact week layout, the icon sprite, the
  draft badge and the undated-assessment control. These have no upstream at all.
* `plugins/dsh-professor-pane/` — the grading and ready views, per-tab subviews,
  the approval strip, `/api/revision` and the Students tab.

**Mirrored by hand**

`plugins/dsh-ainar-course-model/server/` is the same code as `ainar-node/src`,
one build stage later. Upstream a Python script produced it; here the changes are
copied across by hand, minus `roster.ts`, which has no place in a read-only tool
surface. The `.d.ts` files beside them are not maintained — nothing in this
project typechecks against them.
